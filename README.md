# MemBetter

A local-first vocabulary learning app (Memrise / Anki style). Your courses, pictures, audio and progress stay on your
computer; AI help is optional and uses your own keys.

React + Vite + TypeScript renderer inside an Electron shell. Data lives in a local SQLite library.

## Prerequisites

- Node.js >= 22.22
- pnpm 12.x (`npm i -g pnpm`)

## Commands

| Command | Purpose |
|---|---|
| `pnpm install` | Install dependencies (the Electron binary and the SQLite module are fetched on install) |
| `pnpm dev` | Run the desktop app with hot reload. It starts with an empty library kept in its own `MemBetter-dev` data folder |
| `pnpm dev:samples` | Start the development app with the sample course loaded into its own `MemBetter-dev` data folder (only if that library is empty) |
| `pnpm dev:reset` | Delete the data of `pnpm dev` (stored in a separate `MemBetter-dev` folder) so the next run starts empty |
| `pnpm dev:web` | Run only the web renderer in a browser (no storage; used for UI work and for the prototype's "Export my data") |
| `pnpm build` | Type-check and build the app into `out/` |
| `pnpm package:dir` | Build an unpacked app for this computer in `release/` |
| `pnpm package` | Build installers for this computer in `release/` |
| `pnpm samples [file]` | Write `dev-data/sample-courses.membetter` with sample courses for development; load it with **Import** on Home |
| `pnpm test` | Unit and integration tests (Vitest) |
| `pnpm test:e2e` | Build, then end-to-end tests that drive the real app (Playwright) |
| `pnpm test:packaged` | Smoke test of the unpacked macOS arm64 app from `pnpm package:dir` |
| `pnpm lint` / `pnpm typecheck` | ESLint / TypeScript |

## Testing

Run these from the project folder after `pnpm install`.

**Automated checks**

```sh
pnpm typecheck     # TypeScript
pnpm lint          # ESLint
pnpm test          # unit and integration tests (fast, no window)
pnpm test:e2e      # builds the app, then drives the real app with Playwright (opens and closes windows by itself)
```

Run `pnpm test:e2e` with nothing else using the keyboard: some tests type into the app window. Every test uses a temporary data
folder, so none of them touches your own courses.

To run one test file: `pnpm exec vitest run tests/unit/study.test.ts` or `pnpm exec playwright test tests/e2e/practice.spec.ts`.

**By hand**

1. Run `pnpm dev:reset`, then `pnpm dev`. The app opens with an empty library ("You have no courses yet").
2. Create a course, add levels and words (a picture, meaning or example is needed to practice a word), then use the grid button on the
   course card to start **Learn new words**.
3. Try the other features from Home: **Import**, **Export all**, **Import word list**, **Backups**, and the course menu
   (**Export course**, **Export for Anki**, **New words per day**).

## Two places for data: real and sample

| | Data folder | Used by |
|---|---|---|
| **Real** | `~/Library/Application Support/MemBetter` (backups in `~/Documents/MemBetter Backups`) | the installed app |
| **Sample** | `~/Library/Application Support/MemBetter-dev` (backups inside it) | `pnpm dev` and `pnpm dev:samples` |

They never share anything: the installed app never reads the sample folder and ignores the sample file, and the development app never
opens your real library. A development window is titled **MemBetter (sample data)** so you can tell them apart.

## Testing with the sample course

The app contains no sample data. The sample course (12 words in two levels, each with a picture and a recording) is generated by a script:

1. `pnpm dev:samples` writes `dev-data/sample-courses.membetter`, starts the development app and loads the course into the sample folder when
   that library is empty. Run `pnpm dev:reset` to empty the sample folder and start again.
2. Or run `pnpm samples [file]` to only write the file, then use **Import** in the development app. Do not import it into the installed app
   if you want its library to stay your own.

The course has a picture and a recording for every word, so every way to learn can be tried: typing, picking the picture for a word,
picking the word for a picture, hearing a word and picking or typing it, and speed review. The sample has no progress.

## Removing the sample courses (or all test data)

- **Development app (`pnpm dev`):** run `pnpm dev:reset`. It deletes the dev data folder (`MemBetter-dev`), so the next `pnpm dev` starts
  empty. Your installed app is not touched.
- **Installed app:** there is no "remove all" button. Remove courses one at a time from the course menu (**⋮ Remove course**); the sample
  courses have no special status. Removed courses stay in a trash for 30 days. To remove everything at once, quit the app and delete its data
  folder (see "Uninstalling" below).
- The sample file in `dev-data/` is only a file: delete it whenever you like. It is ignored by git.

## Installing on macOS

1. Build the installer: `pnpm package`. This takes about a minute and writes `release/MemBetter-<version>-arm64.dmg` (Apple Silicon) or
   an `x64` file (Intel).
2. Open the `.dmg` and drag **MemBetter** into **Applications**, then open it from Applications or Spotlight.
3. The app is not signed. A build made on your own Mac normally opens straight away. If macOS says the app cannot be opened, right-click
   it, choose **Open** and confirm. If it says the app is damaged, run
   `xattr -dr com.apple.quarantine /Applications/MemBetter.app`.

The installed app starts with an empty library and keeps its data in `~/Library/Application Support/MemBetter`. Automatic backups go
to `~/Documents/MemBetter Backups` (change the folder in **Backups**). It is separate from `pnpm dev`, which uses `MemBetter-dev`.

To try the app without installing it, run `pnpm package:dir` and open `release/mac-arm64/MemBetter.app`.

**Uninstalling:** quit the app and drag **MemBetter** from Applications to the Trash. That removes the program only; your courses stay
on disk. To remove your data as well (this cannot be undone, so use **Export all** first if you want a copy), delete
`~/Library/Application Support/MemBetter`, `~/Documents/MemBetter Backups` and `~/Library/Preferences/com.membetter.app.plist`.
Saved AI keys are in the macOS Keychain under "MemBetter Safe Storage"; remove that item in Keychain Access if you want them gone.

## Exercise types

Practice picks an exercise for each word, like Memrise did (research: `docs/exercises/research.md`): pick the picture for a word, the word for
a picture, the meaning for a word, the word for a meaning; listening (hear it and pick the word, pick the recording, hear it and type it);
and typing with letter tiles. New words get easier choices, words in review get typing and listening. An exercise is only used when the
word has what it needs (a picture, a meaning, audio) and the course has enough other words for the wrong options. Turn types on or off
with the **Exercise types** button in the practice header (for example "No typing"); the choice applies from the next session.

## Speed review

Speed review (from the session picker on a course card) is a game against the clock over the words that are due, like the old Memrise
one (research: `docs/exercises/speed-review-research.md`). Each question is multiple choice with a shrinking time bar (6 seconds, more for long
prompts and recordings) and the screen turns red as time runs out. You have 3 lives (a wrong answer or a timeout costs one; 15 right answers in
a row earn one back, up to 5). A right answer scores 100 plus up to 50 for speed, multiplied by your streak (x2 after 5 in a row, up to x5). The
end screen shows the score, your best on that course and the words you missed; every answer still updates the review schedule.

## Layout

```text
electron/
├── main/        app start, hardened window, media protocol, updates, IPC wiring
├── preload/     the only API the renderer can use (window.api)
├── services/    library, media, exchange (.membetter files), study (FSRS), ai, secrets, backup, anki
├── db/          SQLite connection and forward-only migrations (db/migrations/*.sql)
└── shared/      types and zod schemas used by main, preload and renderer
src/
├── app/         shell and router
├── features/    one folder per feature (home, course-editor, course-detail, practice, library, ai-assistant, privacy, ...)
└── shared/      cross-feature code (api client, media, ui)
scripts/         development helpers (sample courses file); not part of the app
tests/           unit/ (Vitest) and e2e/ (Playwright for Electron)
specs/           feature specifications and plans (Spec Kit); shared design in docs/local-first/
```

## Releasing

Pushing a tag such as `v1.0.0` runs `.github/workflows/release.yml`, which builds installers for macOS, Windows and Linux and
publishes them to the GitHub Release (the installed app looks there for updates). Installers are unsigned unless the signing
secrets listed in the workflow are set: a macOS Developer ID certificate with Apple notarization credentials, and a Windows
code-signing certificate.

See `.specify/memory/constitution.md` for project rules and `docs/local-first/` for the design.
