# Quickstart: Skip AI Generation for Manually-Filled Fields

**Created**: 2026-10-26 | **Feature**: [spec.md](spec.md) | **Data Model**: [data-model.md](data-model.md)

---

## Overview

This document provides runnable validation scenarios to confirm the skip-AI feature works end-to-end. Each scenario is independent and can be tested during development or after implementation.

---

## Prerequisites

1. MemBetter app running in dev mode: `pnpm dev`
2. Sample course with at least one level and word loaded
3. API key configured for Google Generative AI (existing setup)
4. UI editable (word editor tab open)

---

## Validation Scenarios

### Scenario 1: Skip AI When User Pre-fills Meaning

**Goal**: Confirm that pre-filled Meaning field is not regenerated by AI.

**Setup**:
1. Open word editor
2. Add or select a word (e.g., "owl")
3. Manually type a definition in Meaning field: "A nocturnal bird of prey"

**Test**:
1. Click the AI wand (trigger metadata generation)
2. Wait for AI response

**Expected Outcome**:
- Meaning field retains the user-entered text: "A nocturnal bird of prey"
- Other fields (IPA, Example, Images, Audio) are populated by AI
- Meaning field shows a "↷ skipped" badge or icon
- No error messages

**Verification**:
```bash
# Check that AI call did not include Meaning in the request
# (Verify via browser DevTools Network tab or app logs)
# Request body should show skipFields: ["meaning"] or similar
```

**Pass/Fail**: ✓ PASS if user text preserved and badge shown

---

### Scenario 2: Skip AI for Multiple Pre-filled Fields

**Goal**: Confirm all pre-filled fields are skipped (not just one).

**Setup**:
1. Open word editor, select a word
2. Manually fill: Meaning, IPA, Example
   - Meaning: "A large bird"
   - IPA: "/aʊl/"
   - Example: "The owl hooted at night"
3. Leave Images and Audio empty

**Test**:
1. Click the AI wand

**Expected Outcome**:
- Meaning, IPA, Example unchanged (user-entered text preserved)
- Images and Audio populated by AI
- Three skip badges shown (on Meaning, IPA, Example)
- Token cost lower than scenario with no pre-filled fields (~40-50% less)

**Verification**:
```bash
# Monitor API response time and token usage
# Pre-filled + skip: should be ~40-50% fewer tokens than full generation
# (Check app's token usage log if available)
```

**Pass/Fail**: ✓ PASS if all pre-filled preserved, AI-generated fields populated, badges shown

---

### Scenario 3: No AI Call When All Fields Pre-filled

**Goal**: Confirm no AI request is made when all fields are already filled.

**Setup**:
1. Open word editor, select a word
2. Fill all fields manually:
   - Meaning, IPA, Example (text)
   - Images (upload image)
   - Audio (record or upload audio)

**Test**:
1. Click the AI wand

**Expected Outcome**:
- No AI request is sent (no network activity)
- All fields remain unchanged
- No skip badges shown (all fields were pre-filled, no action taken)
- Toast or message: "All fields already filled. No AI help needed." (or similar)

**Verification**:
```bash
# Check Network tab in DevTools: no POST request to Gemini API
# Check app logs: "Skipped AI generation - all fields filled"
```

**Pass/Fail**: ✓ PASS if no API call made, all fields preserved, appropriate message shown

### Scenario 4: Empty Fields Generate Normally

**Goal**: Confirm baseline behavior: all fields empty → all generated by AI.

**Setup**:
1. Open word editor
2. Create a new word entry with only the word text: "elephant"
3. Leave all other fields empty (Meaning, IPA, Example, Images, Audio)

**Test**:
1. Click the AI wand

**Expected Outcome**:
- All fields populated by AI
- No skip badges (no fields were pre-filled)
- Request payload includes all field types (no skipFields)
- Response includes all metadata

**Verification**:
```bash
# Network tab: AI request payload includes all fields
# Response: all fields populated
```

**Pass/Fail**: ✓ PASS if all fields populated, no badges shown, normal flow

---

### Scenario 5: User Clears Field → AI Regenerates on Next Request

**Goal**: Confirm that clearing a previously-filled field allows AI to regenerate it.

**Setup**:
1. From Scenario 1, start with:
   - Meaning: "A nocturnal bird of prey" (user-entered, skipped)
   - IPA: "/aʊl/" (AI-generated)
   - Example: "The owl hooted at night" (AI-generated)
2. Delete the Meaning text (clear the field completely)

**Test**:
1. Click the AI wand again

**Expected Outcome**:
- Meaning field is now regenerated by AI (was empty when request made)
- IPA and Example are skipped (still filled from previous AI call)
- New Meaning may differ from user's original: "A large bird of prey with forward-facing eyes"
- Meaning field shows no "skipped" badge (it was regenerated)
- IPA and Example show "↷ skipped" badges

**Verification**:
```bash
# Network tab: skipFields includes ipa, example but NOT meaning
# Response: includes new meaning value
```

**Pass/Fail**: ✓ PASS if cleared field regenerated, others skipped, badges updated

---

### Scenario 6: Whitespace-Only Content Treated as Empty

**Goal**: Confirm that fields with only whitespace are regenerated by AI.

**Setup**:
1. Open word editor, select a word
2. Fill Meaning with only spaces: "   " (5 spaces, no text)
3. Leave other fields empty

**Test**:
1. Click the AI wand

**Expected Outcome**:
- Meaning is regenerated (whitespace-only is treated as empty)
- No "skipped" badge on Meaning (it was empty, now populated)
- Other fields populated normally

**Verification**:
```bash
# Network tab: skipFields does NOT include meaning
# Response: meaning is populated with AI text
```

**Pass/Fail**: ✓ PASS if whitespace-only fields treated as empty and regenerated

---

### Scenario 7: Visual Feedback Badge Display

**Goal**: Confirm that skip badges are displayed correctly on skipped fields.

**Setup**:
1. From Scenario 1: Meaning pre-filled, others AI-generated
2. Word row should show all fields with appropriate state

**Test**:
1. Visually inspect the word row

**Expected Outcome**:
- Meaning field shows inline "↷ skipped" badge or icon
- Badge is positioned near the field label or at field edge
- Tooltip on hover displays: "This field was not regenerated (already filled manually)"
- Badge color is secondary (M3 design token, not alarming)
- Badges removed/hidden when field is edited or regenerated

**Verification**:
```
# Browser DevTools: Inspect the meaning field DOM
# Should contain: <span class="badge">"↷ skipped"</span> or similar
# CSS: Uses M3 secondary color, shape token for rounded corners
```

**Pass/Fail**: ✓ PASS if badge visible, tooltip works, correct styling applied

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| Skip badges not showing | UI component not rendered or hidden by CSS | Check DOM, verify component import and styling |
| AI regenerates user-filled field | Merge logic not checking existing field | Verify merge: only use AI response if field was empty |
| No API call when some fields filled | skipFields logic too aggressive | Check: skipFields should only include filled fields |
| Whitespace-only treated as filled | trim() not called on field value | Verify: always call `field.trim().length === 0` check |

---

## Summary

These scenarios validate:
1. **Core behavior**: Pre-filled fields skipped, empty fields generated
2. **Data integrity**: User content preserved
3. **Token savings**: API calls reduced when fields are pre-filled
4. **UX clarity**: Visual feedback (badges) helps user understand skip behavior
5. **Edge cases**: Whitespace-only, clearing fields, all fields filled

All scenarios should pass before marking the feature as complete.
